## バックテストでは勝てるのに、本番で勝てない

個人でトレーディング戦略の研究をしています。この半年で40本以上の仮説を統計検定にかけて、**95%を自分で棄却しました**。生き残ったのは2本です。

……と書くと悲惨な成績に見えますが、この記事で伝えたいのは逆のことです。**「95%を棄却できる仕組み」こそが、個人の検証で一番作るのが難しく、一番価値のある部分**でした。トレーディングを例に書きますが、A/Bテストでも機械学習の評価でも、病気と薬は同じです。

個人開発の検証には、構造的な弱点があります。**誰もレビューしてくれない**ことです。

- パラメータを「ちょっと」調整して再実行する
- 期間を「キリのいいところ」に変えてみる
- 指標を「より適切なもの」に差し替える

どれも一つ一つは合理的に見えます。しかし、結果を見てからこれをやった瞬間、あなたのp値は静かに死んでいます。しかもたちが悪いことに、**やった本人に自覚がありません**。これは意志の力では防げません。仕組みで防ぐしかない、というのがこの記事の主張です。

## 薬①：事前登録 — 結果を見る前に、判定基準を書面で固定する

臨床試験の世界からの借り物です。検定を実行する**前に**、次を文書にして固定します。

- **仮説**：何が、どちら向きに効くと主張するのか
- **機構**：なぜ効くはずなのか（これが書けない仮説は登録しない）
- **判定**：検定方法・閾値・合格条件
- **標本**：どのデータで判定するか（主標本と確認標本を分けるならここで）
- **事前予測**：自分はどっちに転ぶと思っているか

最後の「事前予測」が地味に効きます。結果を見た後の「まあ、そうだと思ってたよ」を、過去の自分が許してくれなくなるからです。私は先週、自信のあった仮説の予測を2つ外しました。外した記録が残っているから、次の自信を適切に割り引けます。

一番強い形は「**対象データがまだ手元に存在しない時点で登録する**」です。私は5銘柄×3年分のデータのダウンロードが始まる前に判定基準を固定したことがあります。こうなると「見てから決めた」疑いは物理的に成立しません。

## 薬②：較正ゲート — 既知の答えを再現できない測定器に、本番を見せない

事前登録があっても、まだ足りません。**検定プログラム自体がバグっていたら**、固定した基準で間違った数字を判定するだけだからです。

そこで、すべての検定スクリプトの冒頭にこれを置きます。

```python
from research_discipline import calibration

# この検定ハーネスは、まず「答えを知っている問題」を解かされる。
# 解けなければ例外で停止し、本番データの結果は1行も出力されない。
calibration.gate(
    observed=harness_output_on_known_data(),  # 既知データを自分のコードで測った値
    expected=2.02,                            # 事前に確定している正解
    tolerance=0.15,
    name="dawn-window return on known data",
)
```

大げさに見えますか？ 私はこのゲートに**1日で2回**救われました。

**1回目**：新しい検定スクリプトが、既知の +2.02 を +1.86 としか再現しない。調べると、時間窓のエントリー価格を「窓の中の最初のバーの終値」で取っていました。これは窓開始の**1分後**の価格です。片端1分のクリップ。これだけで答えが帯域から外れ、ゲートが止めました。

**2回目**：修正後の再実行で、今度は結果が空になる。犯人はこれでした。

```python
# polars の dt.hour() は Int8 を返す。
# hour * 60 + minute は最大 1439 → Int8 の上限 127 を黙って超えて巻き戻る
mod = pl.col("time").dt.hour() * 60 + pl.col("time").dt.minute()   # 壊れる
mod = pl.col("time").dt.hour().cast(pl.Int32) * 60 + ...           # 正しい
```

サイレントな整数オーバーフローです。例外は出ません。フィルタが空振りするだけです。ゲートがなければ、私は「片端が1分ズレた測定器」または「何も測っていない測定器」の出力を、事前登録した立派な基準で判定するところでした。

**測定器の故障は、もっともらしい数字を出します。** だから測定器は、本番の前に必ず「答えを知っている問題」を解かされるべきです。これは機械学習の評価スクリプトでも、A/Bテストの集計クエリでも、まったく同じように使えます。

## 薬③：時系列に正直な検定

金融時系列は自己相関とボラティリティ・クラスタリングの塊です。素朴なシャッフルで帰無分布を作ると、現実にはあり得ない「細い」分布ができて、p値が楽観的になります。

平均が正かどうかを検定したいとき、系列をシャッフルしても平均は変わらないので、**ブロック単位で符号を反転**します。ブロックの中の依存構造は保たれたまま、対称な帰無分布が得られます。

```python
from research_discipline import permutation

p = permutation.block_sign_flip_pvalue(daily_returns, block=20, n_perm=2000, seed=42)
```

そして仮説を複数並べたら、**多重比較補正**（Holm法）を必ずかけます。6本の仮説をp<0.05で検定すると、全部ハズレでも約26%の確率で「1本当たる」からです。「いくつか試したら1つ効いた」は、研究が自分で良いニュースを製造する最も典型的な経路です。

## 成績表：95%の棄却は、失敗ではない

この仕組みを通した半年の成績です。

- 検定した仮説：40本以上（教科書戦略37構成、マクロ変数13本、日内アノマリー多数……）
- 生き残り：**2本**
- ゲートが止めた測定器のバグ：複数回（上の2連発を含む）
- 事前予測の的中率：思ったより低い（記録が残っているので言い逃れ不可）

重要なのは、この2本には**「38本の死体の上で生き残った」という含意**があることです。無規律な検証で出てきた「勝てる戦略」と、同じ検定で95%が死ぬ環境を生き延びた戦略は、同じ顔をしていても信頼がまったく違います。

学術の世界では、通貨のアノマリーが論文公表後にリターンを大きく落とすことが知られています（キャリー・モメンタム・バリューの合成はサンプル外でシャープレシオがマイナスに転落したという報告もあります）。個人の検証で「教科書の戦略が全部死んでいる」のは、腕が悪いのではなく、**市場がそういう場所**なのです。だとすれば個人の武器は、聖杯探しの速さではなく、**偽物を見抜く速さ**だと私は考えています。

## まとめ：意志ではなく、構造で

- 結果を見てから基準を動かす自分を、**事前登録**で封じる
- 壊れた測定器を信じる自分を、**較正ゲート**で封じる
- 楽観的なp値を作る自分を、**ブロック順列検定と多重比較補正**で封じる

3つとも「気をつける」では防げません。気をつけるべき本人が汚染源だからです。仕組みだけが自分を守ります。
