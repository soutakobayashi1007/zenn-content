個人でトレーディング戦略の研究をしています。この半年で40本くらいの仮説を統計検定にかけて、38本を自分で棄却しました。残ったのは2本です。

打率だけ見るとひどい成績ですが、いま振り返ると、この「棄却できる仕組み」を作ったことが半年で一番の成果だったと思っています。トレードの話として書きますが、A/Bテストでも機械学習の評価でも事情は同じはずです。

## 個人開発の検証は、誰もレビューしてくれない

会社の分析なら、雑な検証は誰かに突っ込まれます。個人開発では誰も見ていません。

パラメータを少し変えて再実行する。期間をキリのいいところに変える。指標を別のものに差し替える。どれも作業としては自然で、悪気もありません。ただ、結果を見たあとにこれをやると、そのp値はもう当てになりません。しかも本人には、いじった自覚がほとんど残らないんですよね。

意志の力で防ぐのは無理だと途中で悟りました。仕組みで防ぐしかありません。やったことは3つです。

## 事前登録

臨床試験の世界でやっていることの借り物です。検定を実行する前に、次の項目を文書に書いて固定します。

- 仮説と、その機構（なぜ効くはずなのか）
- 判定方法と合格の閾値
- 使うデータの範囲
- 自分の事前予測

書いたら、検定が終わるまで触りません。機構が書けない仮説はそもそも登録しない、というルールも一緒に置きました。

地味に効いたのは最後の「事前予測」です。結果を見てから「まあそうだと思ってた」と言う逃げ道が、過去の自分の書き置きで塞がれます。私は先週、自信のあった予測を2つ外しました。外した記録が残っているので、次に自信があるときはその分を割り引くようになります。

一番効果が強かったのは、対象データのダウンロードが終わる前に判定基準を固定してしまうやり方でした。データが手元にないのだから、見てから決めることが物理的にできません。

## 較正ゲート

事前登録だけだと穴があります。検定プログラム自体がバグっていたら、固定した基準で間違った数字を判定するだけだからです。

そこで、検定スクリプトの先頭にこういう処理を置くことにしました。

```python
from research_discipline import calibration

# 答えがわかっている問題を先に解かせる。解けなければここで止まり、
# 本番データの結果は1行も出力されない
calibration.gate(
    observed=harness_output_on_known_data(),
    expected=2.02,      # 別の方法で確認済みの正解
    tolerance=0.15,
    name="dawn-window return on known data",
)
```

過剰に見えるかもしれません。私はこれに1日で2回助けられました。

1回目。新しく書いた検定スクリプトが、既知の +2.02 という値を +1.86 としか再現しない。調べたら、時間窓の始値を「窓の中の最初のバーの終値」で取っていました。これは窓が開いた1分後の価格です。たった1分のずれで答えが許容範囲から外れて、ゲートが止めました。

2回目。修正して再実行したら、今度は結果が空になりました。原因はこれです。

```python
# polarsのdt.hour()はInt8を返す。hour * 60 + minute は最大1439なので
# Int8の上限127を黙って超えて、値が巻き戻る
mod = pl.col("time").dt.hour() * 60 + pl.col("time").dt.minute()            # 壊れる
mod = pl.col("time").dt.hour().cast(pl.Int32) * 60 + ...                    # 正しい
```

例外は出ません。フィルタが空振りするだけです。ゲートがなければ、1分ずれた測定器か、何も測っていない測定器の出力を、立派な事前登録の基準で判定するところでした。

測定器の故障は、それらしい数字を出してきます。だから測定器には、本番の前に答えのわかっている問題を解かせるべきだと思うようになりました。

## 時系列に合った検定

金融の時系列は自己相関の塊なので、素朴なシャッフルで帰無分布を作るとp値が甘くなります。平均が正かどうかを見たいときは、系列をブロックに区切って符号ごと反転させる方法を使っています。ブロック内の依存構造を保ったまま、対称な帰無分布が作れます。

```python
from research_discipline import permutation

p = permutation.block_sign_flip_pvalue(daily_returns, block=20, n_perm=2000, seed=42)
```

それから、仮説を複数まとめて検定するときは多重比較の補正（Holm法）をかけます。6本の仮説をp<0.05で検定すると、全部ハズレでも4分の1くらいの確率でどれかが「当たって」しまうためです。振り返ると、規律を入れる前の自分が見つけた「有望なパターン」の大半は、これでした。

## 棄却できたことが成果、という感覚

仕組みを通した半年の結果です。

検定した仮説は40本超。教科書に載っているような戦略を37構成、金利差などのマクロ変数を13本、日内のアノマリーをいくつか。生き残ったのは2本でした。

最初は打率の低さにへこみましたが、途中で見方が変わりました。同じ検定で95%が死ぬ環境を生き延びた2本と、緩い検証をすり抜けてきた「勝てる戦略」は、見た目が同じでも信頼がまるで違います。それに、通貨のアノマリーは論文で公表されると収益性が大きく落ちることが知られていて、教科書の戦略が全滅するのは私の腕の問題ではなく、市場がそういう場所だからのようです。

だとすると個人がやるべきことは、聖杯を早く見つけることではなく、偽物を早く見抜くことなのだと思います。
